3.1 Quill.org Anti-Paste Mechanism Analysis
--------------------------------------------------------------------------------
File: `https://www.quill.org/vite/assets/requestWrapper-Dzvsf2ZQ.js` (around offset 2,440,155)

Vulnerable / Restrictive Code in Quill:
```javascript
this.preventPaste = N => (N.preventDefault(), !1);
this.setAnswerBoxRef = N => { this.answerBox = N; };
this.handleKeyDown = N => {
  const { disabled: t, onSubmitResponse: n } = this.props;
  t || N.key !== "Enter" || (N.preventDefault(), n());
};
this.handleTextChange = N => {
  const { disabled: t, onChange: n, surface: r, editorIndex: a } = this.props;
  if (!t) {
    if (r === "contenteditable") {
      const o = N.target.value.replace(/<\/?[^>]+(>|$)/g, "").replace(/&nbsp;/g, " ");
      n(o, this.answerBox);
    } else {
      n(N.target.value, a);
    }
  }
};
this.handleDrop = N => N.preventDefault();

componentDidMount() {
  const { blockPaste: N } = this.props;
  N && window.addEventListener("paste", this.preventPaste, !0); // <-- !0 is capture phase!
}
```

Why standard `document.onpaste = null` fails:
Quill registers the listener directly on `window` with `useCapture = true`. When a paste
occurs, the browser fires `window` capture listeners before target bubbling listeners.
Quill immediately calls `preventDefault()`, preventing the native browser paste.

The Solution (Neutralizing `preventDefault`):
```javascript
const origPreventDefault = Event.prototype.preventDefault;
Event.prototype.preventDefault = function () {
  if (['paste', 'copy', 'cut', 'drop'].includes(this.type)) return;
  return origPreventDefault.apply(this, arguments);
};
```
When Quill executes `N.preventDefault()`, it does nothing. The browser proceeds with the
native paste into the `<textarea class="connect-text-area">`, firing a native `input`
event which React's `onInput={this.handleTextChange}` catches and updates state smoothly.

3.2 Quill Backend API & CMS Architecture
--------------------------------------------------------------------------------
Quill's lesson data is served unauthenticated / session-scoped across several public endpoints:

1. Lesson Structure:
   GET https://www.quill.org/api/v1/lessons/{lessonId}.json
   Returns:
   {
     "name": "Semicolons with However & Therefore - Facts about Ethiopia",
     "questions": [
       { "key": "ec31fbb6-065c-445b-9ded-104afa8e5aca", "questionType": "questions" },
       ...
     ]
   }

2. Question Content & Prompt:
   GET https://www.quill.org/api/v1/questions/{questionId}.json
   Returns:
   {
     "prompt": "<p>Ethiopia has never been colonized by another country. <br/>It was occupied by Italy from 1936 to 1941.<br/></p>",
     "instructions": "Combine the sentences. Use a semicolon and one of the joining words.",
     "cues": "however therefore",
     "question_type": "connect_sentence_combining"
   }

3. Answer Database & Responses:
   GET https://cms.quill.org/questions/{questionId}/responses
   Returns array of objects:
   [
     {
       "id": 32926589,
       "question_uid": "ec31fbb6-065c-445b-9ded-104afa8e5aca",
       "text": "Ethiopia was occupied by Italy from 1936 to 1941; however, it has never been colonized by another country.",
       "optimal": true,    // <-- Critical: indicates 100% correct / optimal sentence
       "weak": false,
       "feedback": "<p>That's a strong sentence!</p>"
     },
     ...
   ]

4. Multiple Choice Options (for diagnostic / proofreader lessons):
   GET https://cms.quill.org/questions/{questionId}/multiple_choice_options
   Returns:
   [
     { "text": "Option A", "correct": true },
     { "text": "Option B", "correct": false }
   ]

3.3 Analysis of MysticalMike60t/quill-cheat
--------------------------------------------------------------------------------
File: `code.js` in https://github.com/MysticalMike60t/quill-cheat

Critical Defects Identified:
1. `document.querySelector(".quill-button")`:
   Old Quill had a button with this class. Current Quill Connect uses React styled components
   with classes like `.button.is-primary`. `waitForQuillButton()` observer enters an infinite loop.
2. `contentDiv = document.querySelector("main")`:
   Appended divs into React's root `<main>` tree, corrupting React 18 DOM hierarchy and causing crashes.
3. `responses.push(responseData[0].text)`:
   Assumed element 0 was always correct. Often element 0 in Quill CMS is an unranked or weak submission.
4. Output formatting:
   Outputted raw UUID strings like `Question: ec31fbb6-065c-445b-9ded-104afa8e5aca` with no prompt or context.
5. No Bookmarklet:
   README claimed bookmarklet was "in development", but it was never completed or released.

5.3 HOW TO REACT AUTO-FILL WORKS UNDER THE HOOD
--------------------------------------------------------------------------------
React overrides the HTML `value` property descriptor with its own synthetic tracker.
Direct assignment (`textarea.value = text`) does NOT trigger React's `onChange`/`onInput`.
The workaround implemented in our assistant:
```javascript
const nativeSetter = Object.getOwnPropertyDescriptor(
  window.HTMLTextAreaElement.prototype, 'value'
)?.set || Object.getOwnPropertyDescriptor(
  window.HTMLInputElement.prototype, 'value'
)?.set;

if (nativeSetter) {
  nativeSetter.call(targetElement, newText);
} else {
  targetElement.value = newText;
}

targetElement.dispatchEvent(new Event('input', { bubbles: true }));
targetElement.dispatchEvent(new Event('change', { bubbles: true }));
targetElement.focus();
```
This forces React's internal fiber node to register the value change immediately,
enabling the "Submit" button without requiring manual keystrokes.
